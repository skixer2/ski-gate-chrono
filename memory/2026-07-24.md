## 08:06 UTC — SGC v4.08: Extended `h` command with frame range

### Change
Extended the `h` serial command to support an optional frame range:

```
h <run_id>              → anchors every 100th frame (unchanged)
h <run_id> <from> <to>  → baro_div2 for EVERY frame in range
```

### Motivation
Phone decompressor showed baro spike at F#612 but `h 0` (anchor mode) was clean — the spike fell between anchors 600 and 700. Need per-frame resolution to isolate whether the encoder, BLE transfer, or decompressor is corrupting the data.

### Files changed
- `src/main.cpp`: `h` command handler — added `Serial.peek()` detection for optional args, range-aware print loop
- `src/config.h`: FW_VERSION 4.07 → 4.08

### Output format (range mode)
```json
{"ev":"hex_dump","id":0,"sz":10764,"range":[600,620],"baro":[[600,40132],[601,40134],...,[620,40258]],"frames":1004}
```

### Output format (anchor mode, unchanged)
```json
{"ev":"hex_dump","id":0,"sz":10764,"anchors":[[0,39860],[100,39860],...],"frames":1004}
```

### Decision tree
- `h 0 600 620` → firmware shows spike at F#612 → encoder bug (bit_packer)
- `h 0 600 620` → firmware shows clean baro → BLE transfer or Dart decompressor bug
